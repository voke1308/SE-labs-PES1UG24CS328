##  Project Overview

**Public Bus Live Tracking** is a Software Engineering lab project focused on applying Agile project management practices using Jira. The project simulates the development of a public transportation tracking system by creating a product backlog, organizing user stories into sprints, estimating effort using story points, and monitoring sprint progress.

The goal is to prioritize essential commuter features first and progressively plan additional capabilities such as crowding estimation, fleet monitoring, and historical data analysis.

##  Objectives

- Create and organize a product backlog using Jira.
- Break down system requirements into manageable user stories.
- Prioritize features based on their importance to commuters.
- Estimate workload using story points.
- Plan and execute two simulated Agile sprints.
- Track sprint progress using the active sprint board and burndown chart.
- Reflect on estimation accuracy, prioritization, and team capacity.

##  Project Features

The backlog covers the following planned system capabilities:

| Feature | Description |
|---|---|
| Route and Stop Search | Search for bus routes and stops. |
| Real-Time Bus Tracking | View live bus locations. |
| Estimated Time of Arrival (ETA) | Calculate real-time bus arrival estimates. |
| Crowding Estimation | Estimate crowding levels using boarding and alighting information. |
| Fleet Monitoring | Monitor fleet performance and detect significant ETA deviations. |
| Service Notifications | Notify users about delayed buses. |
| Historical Data Analysis | View historical GPS and crowding data. |

*Note: These are features represented in the project backlog; this lab focuses on Agile planning and sprint simulation rather than implementing the complete tracking system.*

##  Tools and Technologies

- **Jira Software** — Product backlog, user stories, sprint planning, and progress tracking.
- **Agile Scrum** — Sprint-based planning and delivery simulation.
- **Story Points** — Relative estimation of task complexity and effort.
- **Burndown Chart** — Visualization of remaining sprint workload.

##  Sprint Planning and Execution

### Sprint 1 — Core Tracking Functionality

- **Planned workload:** 3 user stories
- **Total effort:** 13 story points
- **Outcome:** All 3 planned stories completed.

Sprint 1 focused on the core commuter-facing features, including route and stop search, live bus tracking, and real-time ETA calculation.

### Sprint 2 — Advanced Tracking and Monitoring

- **Planned workload:** 6 user stories
- **Total effort:** 24 story points
- **Outcome:** All 6 planned stories completed.

Sprint 2 extended the planned functionality to include crowding estimation, fleet monitoring, ETA deviation detection, delay notifications, and historical data analysis.

##  Project Tracking

The project uses Jira's visual tools to monitor the simulated development process:

- **Product Backlog:** Organizes epics and user stories according to feature requirements and priority.
- **Active Sprint Board:** Tracks work items through their sprint status.
- **Burndown Chart:** Shows the remaining workload against the ideal progress guideline.

The Sprint 2 burndown chart shows the planned workload decreasing from 24 story points to zero, indicating that all committed work was completed within the simulated sprint.

##  Key Learnings

This lab provided practical experience with Agile backlog management and sprint execution.

1. **Estimation:** Story points help represent differences in complexity and expected effort.
2. **Prioritization:** Core commuter features should be addressed before secondary monitoring and historical-analysis capabilities.
3. **Sprint Planning:** Dividing the backlog into smaller sprints makes work easier to organize and monitor.
4. **Progress Tracking:** Sprint boards provide visibility into work status, while burndown charts help compare remaining work with planned progress.
5. **Capacity Management:** Comparing planned and completed story points helps evaluate whether the simulated workload was manageable.

Both simulated sprints were completed successfully, with 37 story points completed across 9 user stories.
